How Unicode Braille Art Generation Works

A deep technical explanation of the 2x4 dot pixel-mapping algorithm used to create high-density Braille text art.

If you've spent time browsing GitHub READMEs or terminal configurations, you have likely seen highly detailed text drawings that look like thin, curvy lines rather than letters. This is Braille Art.

Unlike traditional ASCII art which represents pixels using text characters, Braille art maps pixels to the individual dots within the Unicode Braille character set. This article explains the underlying mathematics and logic behind this technique.

The Unicode Braille block

Unicode includes a block specifically for Braille patterns in the range U+2800 to U+28FF. This block contains 256 characters representing every possible combination of dots in an 8-dot Braille cell.

An 8-dot Braille cell is structured as a grid with 2 columns and 4 rows.

The 2x4 cell mapping layout

In the Unicode standard, each dot in the Braille cell has a specific index number, which maps directly to a bit position in an 8-bit byte (0 to 255).

Dot Grid Layout:
  Col 0         Col 1
┌───────────┐ ┌───────────┐
│ Dot 1 (1) │ │ Dot 4 (8) │
└───────────┘ └───────────┘
┌───────────┐ ┌───────────┐
│ Dot 2 (2) │ │ Dot 5 (16)│
└───────────┘ └───────────┘
┌───────────┐ ┌───────────┐
│ Dot 3 (4) │ │ Dot 6 (32)│
└───────────┘ └───────────┘
┌───────────┐ ┌───────────┐
│ Dot 7 (64)│ │ Dot 8 (128)│
└───────────┘ └───────────┘

The numbers in parentheses represent the binary values (powers of 2) assigned to each dot:

  • Dot 1 (Row 0, Col 0): Bit 0, value 1 (0x01)
  • Dot 2 (Row 1, Col 0): Bit 1, value 2 (0x02)
  • Dot 3 (Row 2, Col 0): Bit 2, value 4 (0x04)
  • Dot 4 (Row 0, Col 1): Bit 3, value 8 (0x08)
  • Dot 5 (Row 1, Col 1): Bit 4, value 16 (0x10)
  • Dot 6 (Row 2, Col 1): Bit 5, value 32 (0x20)
  • Dot 7 (Row 3, Col 0): Bit 6, value 64 (0x40)
  • Dot 8 (Row 3, Col 1): Bit 7, value 128 (0x80)

Calculating the unicode character

To generate a Braille character from a 2x4 pixel block in an image, the algorithm checks the brightness of each of the 8 pixels. If a pixel is dark (below a set contrast threshold), it determines that the corresponding dot should be "active" (drawn).

We initialize an offset byte to 0. For each active pixel in the block, we apply a bitwise OR operation with its corresponding dot value:

let offset = 0;
if (pixelIsDark(0, 0)) offset |= 0x01; // Dot 1
if (pixelIsDark(0, 1)) offset |= 0x02; // Dot 2
if (pixelIsDark(0, 2)) offset |= 0x04; // Dot 3
if (pixelIsDark(1, 0)) offset |= 0x08; // Dot 4
if (pixelIsDark(1, 1)) offset |= 0x10; // Dot 5
if (pixelIsDark(1, 2)) offset |= 0x20; // Dot 6
if (pixelIsDark(0, 3)) offset |= 0x40; // Dot 7
if (pixelIsDark(1, 3)) offset |= 0x80; // Dot 8

The Unicode codepoint is calculated by adding this offset byte to the base address of the Unicode Braille block, which is 0x2800:

const charCode = 0x2800 + offset;
const brailleChar = String.fromCharCode(charCode);

Why Braille is superior to ASCII for resolution

Traditional ASCII art has a resolution constraint: one character represents a single pixel-block. If you want a detailed image, you need a wide screen or very small font sizes.

Braille art effectively quadruples your vertical resolution and doubles your horizontal resolution. Because a single character slot displays a 2x4 dot grid, an output text that is 100 characters wide actually displays a 200-pixel wide grid. This results in incredibly smooth contours, lines, and shapes in environments that only support plain text.
